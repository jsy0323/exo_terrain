The simulation experiment uses `configs/force_estimation_sim.yaml`. It collects 48 episodes of 12 seconds at 100 Hz, with six mass/inertia profiles, four command/perturbation conditions and two sensor-randomized repetitions. Body geometry is fixed. Mass and rotational inertia are physically updated using MuJoCo's model constants. All 48 final episodes completed the stability check.

```powershell
conda activate rsl
Remove-Item Env:PYTHONPATH -ErrorAction SilentlyContinue
python -m force_estimation.collect --config configs/force_estimation_sim.yaml
python -m force_estimation.train --config configs/force_estimation_sim.yaml
python -m force_estimation.evaluate_sim
python -m force_estimation.closed_loop
```

The completed data are in `data/force_estimation_sim_v2_calibrated`. Their manifest records per-episode acceptance, mass profile, motion profile, session, actual speed, command tracking error and contact coverage. `quality_summary.json` summarizes realized conditions. The speed 1st/50th/99th percentiles after warmup are approximately 1.08/1.27/1.72 m/s. These experiments cover the movements actually generated by the current policy. Stable running coverage has yet to be established.

To continue an interrupted acquisition, use the same command with `--resume`. The manifest is atomically updated after each completed episode. To run another acquisition or training experiment, specify a new `--output-dir`.

The calibrated static-start assumption provides each AHRS with an averaged, noisy static accelerometer reading at the initial held pose. Subsequent gravity updates use the noisy gyro and accelerometer stream. The AHRS integrates rotation and rejects acceleration-based corrections during large dynamic discrepancies. True gravity is stored in `imu_ideal` for diagnostics. The first 2 s are excluded from supervised windows, and each valid window spans 100 consecutive valid samples.

A fourth-order causal 30 Hz Butterworth filter operates at the 1 kHz physics rate before downsampling. Gyro/accelerometer signals and torque/ground-force labels share the causal filtering stage. Noise and sensor delays are then applied as configured. Filtered and instantaneous torque labels are both stored, including `tau_total_raw`, `tau_bio_raw`, `tau_applied_raw` and `grf_v_raw`. The 30 Hz output target has the latency inherent to causal filtering.

FSR calibration is simulated using known static loads of 0, 25, 50, 100, 200, 400, 800 and 1200 N, with noisy normalized readings. The inverse calibration curve converts FSR response into a force proxy for engineered features. Each episode stores its four calibration curves. The temporal FSR model still contributes lag, creep, bias and noise during movement. A 2% per-episode sensor loss probability and short random IMU interruptions exercise the availability masks and derived-feature masking.

The new estimator predicts `tau_total`, the filtered net joint demand. The dataset also contains `tau_bio=tau_total-tau_applied`. External joint moments are known exactly for the ideal-source experiment. A pure wearable estimator can therefore be used with an external subtraction at the control boundary,

\[
\hat\tau_{bio}=\hat\tau_{total}-\tau_{applied},\qquad
\tau_{desired}=a\,\hat\tau_{bio}.
\]

The closed-loop controller uses the known filtered applied moment for this subtraction. A 4 N m amplitude limit and 40 N m/s slew limit are simulation experiment parameters. Human movement comes from the existing locomotion policy reacting to its observations. Interpretation of these experiments is limited to that simulated policy and ideal torque transmission.

Training uses mass profiles 0.94, 1.00, 1.03 and 1.06 for training, 0.97 for validation, and 1.09 for testing. Episodes from each held-out mass profile remain together. This produces 32 training, 8 validation and 8 test episodes. The geometry and locomotion-policy family are shared across these profiles. Rare high-amplitude or fast-changing hip labels receive increased sampling probability using training data only. Validation residuals calibrate the predicted standard deviations, and test labels are reserved for final evaluation.

The selected model is `models/force_estimator_sim_v2/model_best.pt`, epoch 43. Its held-out mass-profile hip MAE is approximately 3.89/2.67 N m. On the same AHRS-input episodes, the earlier estimator gives 14.70/11.57 N m. This comparison evaluates the full pipeline changes and their associated training data. The comparison against instantaneous raw biological moments gives 6.12/5.84 N m for the improved model. Results and a waveform plot are in `models/force_estimator_sim_v2/evaluation`.

The held-out test's calibrated +/-2 sigma coverage is approximately 90.5% on the left and 96.6% on the right. Coverage on the unseen mass profile remains an uncertainty-calibration limitation. The code stores the calibration factors with the checkpoint, and `OnlineMomentEstimator` applies them when loading that checkpoint.

The paired closed-loop trials use the same two seeds for gains 0, 0.1 and 0.2, with results in `logs/force_estimation_closed_loop/summary.json`. All six trials complete 12 seconds. At gain 0.2 the requested torque exceeds the 4 N m amplitude limit for approximately 58%/44% of evaluated left/right samples. The achieved torque follows the configured amplitude and slew limits.

The follow-up [hip MAE fine-tuning experiment](MAE_IMPROVEMENT.md) selects a new checkpoint with test hip MAE 3.04/2.25 Nm. That document records the controlled ablation, selected checkpoint, figures, latency and closed-loop results.

Loading a calibrated simulated sensor recording requires its subject values and its FSR calibration curves.

The output directory `models/force_estimator_sim_v2/results` contains five PNG/SVG figures and the five-page `estimator_results.pdf`: training, hip waveforms across four conditions, test accuracy and uncertainty coverage, knee/ankle/GRF outputs, and contact/gait phase. Waveforms use 100 Hz predictions from the first test episode in each condition without extra smoothing or time alignment. Aggregate metrics use the checkpoint's saved evaluation stride (10 samples here, 728 windows). The `results.json` records the checkpoint hash and metrics; `test_predictions.npz` stores the predictions, labels, timestamps, episode indices and evaluation mask. Optional flags are `--checkpoint`, `--data-dir`, `--output-dir`, and `--seconds`.

```python
import json
import numpy as np
from force_estimation.runtime import OnlineMomentEstimator

episode = np.load("data/force_estimation_sim_v2_calibrated/episode_00040.npz")
metadata = json.loads(str(episode["metadata"]))
estimator = OnlineMomentEstimator(
    "models/force_estimator_sim_v2/model_best.pt",
    metadata["subject"],
    fsr_calibration_curves=metadata["randomization"]["fsr_calibration_curves"],
)
for index, timestamp in enumerate(episode["time"]):
    prediction = estimator.step(timestamp, episode["imu"][index], episode["imu_mask"][index],
                                episode["encoder"][index, :2], episode["fsr"][index])
    # prediction["tau_hip"] represents total net hip demand in N m.
```
